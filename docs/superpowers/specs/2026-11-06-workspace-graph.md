# 工作区统一节点模型
用户要求升级产品功能，天气自动化仅作后续案例，不创建定时通知。工作区统一承载会话、任务、自动化、Context、记忆和空间设置。Agent 是可配置的执行卡牌，其他对象使用各自节点形态。共享资源通过明确引用连接，任务历史仍隔离。

实现统一工作区画布与目录，复用现有 Space/Session、Agent/task、trigger、memory 的原始 ID 与 API。画布布局不复制业务记录；在目录和画布编辑同一资源。会话为容器节点，自动化为触发节点，Context为可编辑资料节点，记忆为既有 space 记忆条目，设置节点打开现有空间设置。Agent采用游戏卡牌的信息分区（名称、角色、模型、能力、运行状态），保留既有视觉系统与编辑/运行能力。

新建 Context 资料和每个 Agent 的 Context/记忆引用持久化到本地后端。执行前解析所属工作区的被选资源，保存不可变版本快照；资料不是系统指令，作为引用内容给模型。缺失资源应明确失败，跨工作区引用拒绝。原有会话/手动转交继续可用。

工作区自动化展示现有 trigger 与其生成会话的关系，并支持把 trigger 绑定到现有 Agent/团队作为执行目标。沿用已有调度/通知与执行去重机制；执行流程从已配置目标实例化到新会话，记录来源。界面明确本机自动执行需要 AgentDeck 后台在线，不宣称关机后运行。本次不配置天气定时和外部通知。

所有原数据保留。只向 ming-own/agent-deck 推送。保留模型连接凭据的现有临时传递方式，不持久化密钥。新增界面中文/英文完整，其他语言使用既有fallback或逐项补齐。
