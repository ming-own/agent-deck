# AgentDeck（智牌）

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The owner develops and operates a personal, locally running, configurable Agent workspace. The desktop application is an Electron-hosted React interface.

## Product Purpose

A workspace unites Sessions, Tasks, Automations, Context, Memory, and space settings on an infinite canvas. Agents are configurable nodes, not fixed execution modes. Each Agent can choose its own model, role, instructions, Skills, and Harness; Tasks retain independent histories inside Sessions.

## Capabilities and Constraints

Existing capabilities include Session regions, persisted node positions, Agent-to-Agent trial execution, manual answer handoff with source snapshots, conditional and parallel routing, resource references, and automation bindings. Preserve these behaviors and all canonical account, space, project, agent, and task identities. Current automations require the desktop runtime; do not imply an unattended cloud service exists.

Models are connections, independent from Agent identity. Workforce is a reusable Agent form. Node categories must express real behavior; appearance must not silently change execution behavior or context ownership.

## Brand Commitments

The repository product name is AgentDeck（智牌）. The owner requested full-frame trading-card-inspired nodes, referencing Yu-Gi-Oh, with distinct categories and a Workshop for designing cards. Keep the application's compact operational shell readable while exploring a replacement visual world for the canvas, cards, and Workshop.

On 2026-11-06 the owner explicitly chose visual mockups for approval before implementation. The owner approved the three mockups and authorized implementation later that day, starting with design → save → instantiate. Reference-only Yu-Gi-Oh artwork is not a shipping asset.

## Evidence on Hand

The local repository, `docs/agentdeck-roadmap.md`, existing local preview screenshots, and the owner's task history establish current product behavior. Design mockups may use clearly identified illustrative workflows; they do not prove that those workflows have run or that scheduling is enabled.

## Product Principles

- Configuration and composition apply to arbitrary nodes, not one hard-coded demonstration.
- A Session isolates records; each Task owns its context and continuation.
- Shared resources require explicit references.
- Card design and actual capability must remain connected in the product.
- Preserve source attribution and licenses; only publish to the owner's repository.
